# te — рабочие заметки

Детали, которые не нужны для чтения [README](README.md): чего не хватает в FRR,
грабли, найденные по ходу, и что ещё не проверено.

## Чего в FRR нет

Штатной ручки «задай явный путь для SRv6» в FRR 10.7 не существует:

- **pathd не годится.** `segment-routing traffic-eng` умеет segment-list только
  из MPLS-меток: в грамматике `index (0-...) [mpls label (16-1048575) | nai ...]`,
  варианта `ipv6-address` нет. `nai` — подсказка для PCE, результат всё равно метка.
- **Flex-Algo только для MPLS.** В документации isisd прямо: «on an MPLS
  Segment-Routing dataplane». Для SRv6 понадобился бы локатор на каждый алгоритм,
  а в FRR открыта задача #18420 «currently FRR supports a single SRv6 locator».
- **BGP color/ODN steering для SRv6 нет.** PCEP и BGP SR-Policy — тоже нет.
- **`sharpd` не подходит** для внешнего управления: только CLI, SID-листов нет.

## Проверка пути дампом

Ещё один признак пути — по каким узлам вообще есть непустые pcap. Для маршрута
через P1-P2-P4-P3 файлов у PE4 быть не должно.

## Грабли

- **`nexthop vpn export` ломает eBGP-выученные префиксы.** Next-hop начинает
  резолвиться внутри VRF (в выводе `fc00::11@3`, где 3 — vrf id RED), а адрес
  живёт в default VRF. Маршрут становится invalid, `not allocated`. Локальные
  префиксы от `redistribute connected` при этом проходят, потому что у них
  weight 32768 и проверка next-hop не выполняется — из-за этого кажется, что
  работает частично. Решение: убрать строку совсем.

- **Без `sid vpn export` DT4-сид не выделяется вообще.** Убрали строку — End.DT4
  исчез из `show segment-routing srv6 sid`, VPN перестал работать. Стоит `auto`.

- **End.X от isisd занимают младшие индексы функции.** При явном `sid vpn export 1`
  будет конфликт; брать заведомо больший, например 100.

- **`clear bgp vrf RED ipv4 unicast *` нужен при холодном старте**, иначе префиксы
  от CE не экспортируются в VPN. Триггером служит сам факт правки, см. FRR #10623.
  В `setup.sh` вшито, но срабатывает не всегда — если после деплоя в
  `show bgp ipv4 vpn` на рефлекторе меньше четырёх RD, повторить руками по всем PE.

- **`bgp retain route-target all` в FRR включён по умолчанию**, поэтому рефлектор
  без единой VRF не выбрасывает VPN-маршруты. На Cisco пришлось бы писать руками.

- **`ip route ... segments` работает только с интерфейсом из той же VRF.** С `lo`
  (default VRF) zebra молча выбрасывает маршрут, в RIB его нет вовсе. С `eth3`
  (в VRF RED) встаёт нормально.

- **`label=16` в выводе VPNv4 — не MPLS.** Метка идёт заглушкой рядом с настоящим
  SRv6-сидом: `label=16 sid=fc00:13:: sid_structure=[40,24,16,0]`. Форвардинг
  полностью SRv6.

- **VRF и sysctl не переживают рестарт контейнера** — они создаются через `exec`
  в containerlab. После перезапуска WSL нужен полный передеплой.
  Линки тоже: veth-пары после рестарта не восстанавливаются, в контейнере
  остаётся только `eth0`, а FRR по-прежнему показывает `interface eth1..4`
  с адресами из конфига. Признак — в `show isis database` один свой LSP.

- **ECMP на CE не размазывает один ICMP-поток** — все пакеты идут на один PE.
  Чтобы зафиксировать сторону для теста TE, поставить weight:
  `neighbor 192.168.11.2 weight 200` на CE1.

- **Узловой End в ядро не устанавливается.** isisd показывает `fc00:1:: End`
  в `show segment-routing srv6 sid`, но в таблице ядра только End.X. Так на 5.15,
  6.6 и 6.18. Причина не выяснена, на TE не влияет — путь строится на End.X.

- **Рёбра в TED зависят от порядка появления адресов.** isisd кладёт в LSP
  `Local Interface IPv6 Address` только по событию «адрес добавлен». Адрес,
  появившийся на интерфейсе до `mpls-te on`, в TE не попадает, и TED не может
  собрать ребро: вершины и префиксы есть, рёбер нет. При старте это гонка по
  интерфейсам, после чистого деплоя было 13 рёбер из 24. Выключить и включить
  `mpls-te` не помогает. `setup.sh` после сходимости IS-IS снимает и возвращает
  адреса линков и ждёт 24 ребра — не сразу, isisd придерживает генерацию LSP.

- **Снять и вернуть адрес одним вызовом vtysh нельзя.** Все `-c` одного вызова —
  одна транзакция, `no ipv6 address` и `ipv6 address` схлопываются в ноль:
  `No changes found to be committed!`. Нужны два вызова. При этом для адресов
  интерфейсов та же надпись бывает и при реально применённой правке — верить
  ей нельзя, проверять по `ip -6 addr`.

- **Поведение SID в TED и BGP-LS показано числом.** На рёбрах
  `IPv6 Adjacency-SRV6-SID ... behavior: 0x5`, в JSON BGP-LS `"behavior":"0x5"`,
  где 5 — End.X по реестру IANA. `grep End.X` по TED ничего не находит.

## Что не проверено

- **TI-LFA.** `isis fast-reroute ti-lfa` в FRR есть и должна строить
  многосегментные обходы при отказе линка автоматически. На старом ядре упёрлась бы
  в тот же баг End.X; на 6.18 имеет смысл проверить — что именно генерируется
  и за сколько происходит переключение.
- **Контроллер, пишущий сиды на PE.** Варианты южного интерфейса: netlink напрямую
  (чище всего, политика живёт в контроллере), zebra API, или `vtysh -c` по SSH.
  Топологию можно брать через BGP-LS: в FRR 10.7 он есть с поддержкой SRv6,
  анонсирует локаторы, End, End.X и структуру SID.
- **Вторая VRF.** В `basic/` их две, здесь BLUE убрана как лишняя для TE.
